\chapter*{Executive Summary}
\addcontentsline{toc}{chapter}{Executive Summary}

BotMe is an advanced AI Persona Chatbot Platform designed to bridge the gap between generic large language models and personalized digital communication. In an era where digital interactions form a significant part of human connection, the ability to preserve and replicate individual communication styles has become increasingly relevant. This project addresses the challenge of creating AI agents that not only understand language but also embody specific personalities derived from real-world data.

The system allows users to upload WhatsApp chat export files, which are then processed to create distinct AI personas. Leveraging Retrieval-Augmented Generation (RAG) technology, BotMe utilizes ChromaDB as a vector database to store and retrieve context-aware conversation fragments. This ensures that the AI remembers past interactions and responds in a manner consistent with the original user's style. The platform is built on a robust tech stack featuring a React-based frontend for a modern, responsive user interface and a Flask backend powered by LangChain and OpenAI's GPT-4o-mini model.

Key features include automated personality analysis using the Big Five (OCEAN) traits model, secure authentication via email/password and Google OAuth, and a comprehensive admin panel for system management. The outcome is a scalable, secure, and highly interactive platform that successfully demonstrates the potential of personalized AI in preserving digital legacies and enhancing user-bot interactions.

\chapter{Introduction}

\section{Background}
The advancement of Large Language Models (LLMs) has revolutionized the field of Artificial Intelligence, enabling machines to understand and generate human-like text with remarkable accuracy. However, most existing AI chatbots, such as ChatGPT or Gemini, operate as generic assistants. While they possess vast general knowledge, they lack the specific personal context, memories, and unique communication styles that define individual human interactions. Digital communication, particularly through platforms like WhatsApp, has become a primary medium for personal expression, creating rich archives of behavioral data that remain largely underutilized.

\section{Problem Statement}
There is a significant gap in the current AI landscape regarding personalization. Users today interact with "one-size-fits-all" AI models that cannot mimic specific individuals. This limitation becomes critical in scenarios such as digital legacy preservation, where families might wish to interact with a digital persona of a loved one, or in personalized customer service, where a brand's specific tone and history are bespoke. Furthermore, raw chat logs (e.g., WhatsApp exports) are unstructured and difficult to browse, making the valuable memories and personality traits buried within them inaccessible for interactive use.

\section{Proposed Solution}
BotMe proposes a web-based AI Persona Chatbot Platform that automates the conversion of unstructured WhatsApp chat data into interactive, memory-aware AI agents. By integrating Retrieval-Augmented Generation (RAG) with a vector database (ChromaDB), the system retrieves relevant past conversations to inform current responses, effectively simulating "memory." The platform also employs personality analysis algorithms to quantify and replicate the user's communication style based on the Big Five personality traits.

\section{Objectives}
The primary objectives of the BotMe project are:
\begin{itemize}
    \item To develop a system that parses and processes WhatsApp chat export files (.txt) into structured data.
    \item To implement a RAG-based chatbot architecture that uses vector embeddings to maintain context and memory.
    \item To create a personality analysis module that evaluates chat data against the Big Five personality traits.
    \item To build a secure, modern web application with role-based access control (Admin/User).
    \item To provide a user-friendly interface for managing multiple AI personas.
\end{itemize}

\section{Scope}
The scope of BotMe includes the development of a full-stack web application. The backend handles data processing, vector embedding, and LLM interaction, while the frontend provides a responsive interface for users.
\textbf{In Scope:}
\begin{itemize}
    \item Text-based chat functionality.
    \item WhatsApp .txt file support.
    \item English language processing.
    \item User and Admin roles.
\end{itemize}
\textbf{Out of Scope:}
\begin{itemize}
    \item Voice or video call simulations.
    \item Real-time integration with live WhatsApp accounts (uses exports only).
    \item Multi-lingual support beyond English.
\end{itemize}

\section{Stakeholders}
\begin{itemize}
    \item \textbf{General Users:} Individuals wanting to create digital personas of friends, family, or themselves.
    \item \textbf{Researchers/Developers:} Those interested in NLP and personalized AI behaviors.
    \item \textbf{Administrators:} System maintainers responsible for user management and content moderation.
\end{itemize}

\section{System Boundaries}
The system operates as a standalone web application. It interacts with external services (OpenAI API for LLM processing, Google OAuth for authentication) but manages its own database and file storage. User data is processed and stored within the application's secure environment.

\section{Constraints}
\begin{itemize}
    \item \textbf{Data Privacy:} Chat logs contain sensitive personal information; the system must ensure strict access control.
    \item \textbf{API Costs:} Reliance on OpenAI's API incurs costs based on token usage.
    \item \textbf{File Format:} Currently limited to standard WhatsApp export formats.
\end{itemize}

\section{Tools & Technologies}
The project utilizes a modern and robust technology stack:
\begin{itemize}
    \item \textbf{Frontend:} React 18, Vite, Tailwind CSS, Framer Motion, Axios.
    \item \textbf{Backend:} Flask, Flask-SQLAlchemy, LangChain.
    \item \textbf{AI/ML:} OpenAI GPT-4o-mini, ChromaDB (Vector Store), All-MiniLM-L6-v2 (Embeddings).
    \item \textbf{Database:} SQLite (Relational), ChromaDB (Vector).
\end{itemize}

\chapter{Literature Review}

\section{Existing Chatbot Systems}
Traditional chatbots relied on rule-based systems (e.g., ELIZA), which matched keywords to pre-scripted responses. While functional for simple tasks, they lacked contextual understanding. Modern implementations like ChatGPT utilize Transformer architectures to generate human-like text. However, these models are static after training; they do not "know" a specific user's history unless it is manually provided in the prompt context window, which is limited in size and retention.

\section{Retrieval-Augmented Generation (RAG)}
RAG is a paradigm that enhances LLMs by retrieving relevant document chunks from an external knowledge base before generating a response. Unlike fine-tuning, which requires expensive retraining of the model, RAG allows for dynamic knowledge updates. Research by Lewis et al. (2020) demonstrated that RAG significantly reduces hallucinations and improves factual accuracy by grounding the model in retrieved data. BotMe applies this concept to "personal memory," treating chat logs as the knowledge base.

\section{Personality Modeling in AI}
Personality computing involves the automated recognition and synthesis of human personality. The most widely accepted model is the Big Five (OCEAN: Openness, Conscientiousness, Extraversion, Agreeableness, Neuroticism). Studies have shown that linguistic patterns—such as word choice, sentence length, and emoji usage—correlate strongly with these traits. By analyzing a user's chat history, an AI can determine their personality profile and adjust its generation parameters (e.g., temperature, verbosity) to match.

\section{Research Gaps}
Existing platforms like Character.AI rely on users manually writing descriptions to define a persona (e.g., "You are helpful and kind"). This approach is subjective and fails to capture the subtle nuances of a real person's speech. There is a lack of accessible tools that can ingest raw behavioral data (chat logs) to automatically generate high-fidelity personas without manual prompt engineering. BotMe assists in filling this gap by automating the data-to-persona pipeline.

\section{Overall System Architecture}
BotMe follows a modular Client-Server architecture. The Client is a Single Page Application (SPA) built with React, ensuring a smooth interactive experience. The Server is a RESTful API built with Flask, serving as the bridge between the frontend, the database, and the AI services.

\section{System Workflow}
1.  \textbf{Authentication:} User logs in via Email or Google OAuth.
2.  \textbf{Upload:} User uploads a WhatsApp \texttt{.txt} export file.
3.  \textbf{Parsing:} The system cleans the text, removing timestamps and system messages, and separates dialogues by speaker.
4.  \textbf{Embedding:} Text chunks are converted into vector embeddings using the \texttt{all-MiniLM-L6-v2} model.
5.  \textbf{Storage:} Vectors are stored in ChromaDB; metadata (personas) is stored in SQLite.
6.  \textbf{Interaction:} When a user chats, the query is embedded, relevant past chats are retrieved from ChromaDB, and sent to GPT-4o-mini to generate a response in the persona's style.

\section{Frontend Design}
The frontend emphasizes user experience with a "Dark Mode" first design using Tailwind CSS.
\begin{itemize}
    \item \textbf{Dashboard:} Displays created personas and personality stats.
    \item \textbf{Chat Interface:} A familiar messenger-style layout with message bubbles, typing indicators, and auto-scroll.
    \item \textbf{Visuals:} Framer Motion is used for smooth transitions between pages and modal popups.
\end{itemize}

\section{Backend Design}
The Flask backend is organized into blueprints for scalability:
\begin{itemize}
    \item \textbf{Auth Blueprint:} Handles login, registration, and session management using Flask-Login.
    \item \textbf{Main Blueprint:} Manages file uploads parsing logic using custom RegEx patterns for WhatsApp formats.
    \item \textbf{Chat Blueprint:} Manages API endpoints for sending messages and retrieving chat history.
\end{itemize}
The backend utilizes \texttt{LangChain} to seamlessly chain the retrieval and generation steps (RAG pipeline).

\section{Database Design}
The system uses a hybrid database approach:
\begin{itemize}
    \item \textbf{SQLite (Relational):} Stores structured data such as Users (`id`, `email`, `password_hash`), Personas (`id`, `name`, `user_id`), and ChatSessions.
    \item \textbf{ChromaDB (Vector):} Stores high-dimensional vector representations of the chat content for semantic search.
\end{itemize}

\section{RAG Chatbot Design}
The core intelligence lies in the RAG module.
\begin{enumerate}
    \item \textbf{Retrieval:} The user's query is converted to a vector. ChromaDB performs a similarity search (Cosine Similarity) to find the top $k$ most relevant past message pairs.
    \item \textbf{Augmentation:} These retrieved snippets are injected into the system prompt: \textit{"You are [Persona Name]. Speak like them based on these past examples: [Examples]..."}.
    \item \textbf{Generation:} GPT-4o-mini generates the response, which is returned to the user.
\end{enumerate}

\section{Personality Analysis Module}
This module analyzes the uploaded text file to extract linguistic markers. It calculates:
\begin{itemize}
    \item \textbf{Vocabulary Richness:} Unique words vs. total words.
    \item \textbf{Sentiment Score:} Positive vs. negative tone using NLTK/TextBlob.
    \item \textbf{Big Five Traits:} Heuristic analysis mapping keywords to Openness, Conscientiousness, Extraversion, Agreeableness, and Neuroticism.
\end{itemize}

\section{Admin Panel}
A dedicated route protected by an \texttt{@admin\_required} decorator.
\begin{itemize}
    \item \textbf{User Management:} List all registered users, view their email and join date.
    \item \textbf{Controls:} ability to delete users or revoke access.
    \item \textbf{Stats:} View total system usage metrics (number of personas, messages exchanged).
\end{itemize}

\section{Security Implementation}
\begin{itemize}
    \item \textbf{Password Hashing:} Uses \texttt{Werkzeug} security helpers generate and check password hashes.
    \item \textbf{OAuth:} Secure Google login flow preventing credential theft.
    \item \textbf{Data Isolation:} Each user can only access personas and chats they created (Row-Level Security enforced via application logic).
\end{itemize}

\section{Testing Strategy}
We employed a combination of Black Box and White Box testing strategies.
\begin{itemize}
    \item \textbf{Unit Testing:} Individual functions (e.g., chat parsers) were tested with various input formats to ensure robustness against broken files.
    \item \textbf{Integration Testing:} Verified the communication between the React frontend and Flask backend using Axios interceptors.
    \item \textbf{User Acceptance Testing (UAT):} Users uploaded their own chats to verify if the bot "sounded" like the target person.
\end{itemize}

\chapter{Conclusion & Future Work}

\section{Achievements}
BotMe has successfully met its core objectives. We have delivered a fully functional platform that:
1.  Democratizes the creation of AI personas from raw data.
2.  Secures user data while providing powerful AI capabilities.
3.  Demonstrates the practical application of RAG for hyper-personalization.
The integration of personality metrics adds a layer of depth, making the AI feel more "human" and less like a generic tool.

\section{Limitations}
\begin{itemize}
    \item \textbf{Data Dependency:} The quality of the persona is strictly limited by the quality and quantity of the uploaded chat logs. Sparse data leads to generic responses.
    \item \textbf{Context Window:} While RAG helps, extremely long-term dependencies or understanding complex multi-turn reasoning outside the retrieved chunks can still be challenging.
    \item \textbf{Text Only:} Currently, the system does not support voice notes or images found in WhatsApp exports.
\end{itemize}

\section{Future Enhancements}
\begin{itemize}
    \item \textbf{Multi-modal Support:} Integrating OpenAI's Whisper API to transcribe and learn from voice notes included in chat exports.
    \item \textbf{Fine-Tuning Pipeline:} Allowing users to perform LoRA (Low-Rank Adaptation) fine-tuning on their data for even higher fidelity style mimicry.
    \item \textbf{Live Integration:} Developing a browser extension or mobile wrapper to intercept live messages for real-time memory updates.
\end{itemize}

\section{Conclusion}
BotMe represents a significant step forward in personalized AI. By moving away from static prompts and leveraging dynamic memory retrieval, we have created a system that preserves the digital essence of individuals. This project not only serves as a technical demonstration of modern web and AI technologies but also opens conversations about the future of digital identity and legacy in the age of Artificial Intelligence.
